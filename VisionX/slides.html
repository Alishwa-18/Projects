● THE PROBLEM
Why do we need real-time
computer vision in the browser?
📡
Server Dependency
Traditional vision systems upload frames to a backend server for processing — introducing latency, bandwidth costs, and privacy risks. Not feasible for real-time interactions.
⏳
High Latency
Round-trip network calls add 200–500ms of delay, making real-time applications like gesture control, live AR, or interactive analytics feel sluggish and unresponsive.
🔒
Privacy Concerns
Sending webcam frames to cloud servers raises serious privacy and data security concerns, especially for facial analysis applications in educational or medical contexts.
💸
Deployment Complexity
Existing vision tools require Python environments, GPU servers, Docker, and complex APIs — creating a barrier for students, educators, and small-scale developers.

● MODULE 1 · GESTURE RECOGNITION
21 Hand Landmarks →
12+ Classified Gestures
Algorithm Steps
1
Capture video frame via MediaPipe Camera
2
Run Hand Landmark Detection (21 points, 3D)
3
Extract TIP and PIP joint y-coordinates per finger
4
Determine finger up/down state (TIP.y < PIP.y)
5
Map 5-bit finger vector → Gesture class
6
Draw skeleton overlay + emoji label on canvas
2 hands simultaneously  ~3ms per frame  WebGL accelerated

● MODULE 2 · COLOR ANALYZER
Pixel Quantization →
Live Color Intelligence
How Color Extraction Works
1
Downscale frame to 160×120 for performance
2
Sample every 4th pixel → ~1,200 color samples
3
Bit-shift quantization: R>>5, G>>5, B>>5 (bucket)
4
Sort buckets by frequency → top 6 dominant colors
5
Match to 45-color named database (Euclidean distance)
6
Compute HSL, brightness, temperature, variance
🎨 Color temperature = (avgR − avgB + 255) / 510
💡 Brightness = 0.299R + 0.587G + 0.114B (Luma)
